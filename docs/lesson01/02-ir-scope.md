# 第 1 课第 2 节：最小语言与性能基线

## 输入语言

编译器接受包含一个或多个函数的模块。函数参数是输入张量，函数结果是输出张量。每个张量只有静态形状，元素类型固定为 `f32`。第一版只有三个计算操作：

| 操作 | 合法输入 | 结果类型 | 语义 |
| --- | --- | --- | --- |
| `add(A, B)` | `A, B: tensor<Lxf32>`，同一长度 `L > 0` 且 `L % 4 == 0` | `tensor<Lxf32>` | `C[i] = A[i] + B[i]` |
| `relu(A)` | `A: tensor<Lxf32>`，`L > 0` 且 `L % 4 == 0` | `tensor<Lxf32>` | `C[i] = max(A[i], 0)` |
| `matmul(A, B)` | `A: tensor<MxKxf32>`、`B: tensor<KxNxf32>`，`M, K, N > 0` 且均为 16 的倍数 | `tensor<MxNxf32>` | `C[m,n] = Σₖ A[m,k] × B[k,n]` |

`add` 的两个输入必须同形状，`relu` 的输入与结果同形状。`matmul` 的左输入列数必须等于右输入行数。例如，`matmul(tensor<16x32xf32>, tensor<32x16xf32>)` 产生 `tensor<16x16xf32>`；第二个输入若为 `tensor<16x32xf32>`，内维 `32 != 16`，必须拒绝。函数声明的结果类型也必须与计算结果一致。

当前只接受有限 `f32` 测试数据。矩阵乘法的 GPU 路径可以使用 FMA，测试与 CPU 参考结果采用约定的浮点容差，而不要求逐位相等。张量维度与缓冲区地址的约束在进入 PTX 后端前再次校验；一维缓冲区地址保证 16 字节对齐。

## 必须拒绝的输入

- 非 `f32` 类型，例如 `tensor<1024xf16>`，或同一算子的输入/声明结果元素类型不一致。
- `add` 两个输入长度不同，或 `matmul` 的内维不同。
- 一维长度不是 4 的倍数，或矩阵任一维不是 16 的倍数。
- 零维度、未定义的 SSA 值、重复定义的 SSA 值、函数声明结果与实际返回结果不一致。
- 不在上述三种计算操作中的未知操作。

前两项直接来自本节的类型和形状契约；SSA 错误和未知操作会在第 3 课的解析与校验器中实现。

## 未优化性能基线

`--opt-level=0` 先为每个计算操作生成一个独立的朴素 kernel，便于逐项比较优化。`relu(add(A,B))` 在长度 `L=1024` 时有两个 kernel：

| Kernel | 全局读取 | 全局写入 |
| --- | ---: | ---: |
| `add` | `2L` 个 `f32` | `L` 个 `f32` 中间结果 |
| `relu` | `L` 个 `f32` 中间结果 | `L` 个 `f32` 输出 |
| 合计 | `3L` 个 `f32` | `2L` 个 `f32` |

合计为 `5L × 4 = 20,480` 字节的源码层面全局读写量，以及两次 kernel launch。融合成一个 kernel 后是 `3L × 4 = 12,288` 字节和一次 launch；理论上减少 8,192 字节中间结果读写。实际 DRAM 流量和延迟受缓存、launch 开销等影响，必须另行测量。

对 `16×16` 乘 `16×16` 的朴素 `matmul`，每个输出计算 16 次乘加，每次读取 A、B 各一个元素，因此源码层面有 `16×16×16×2 = 8,192` 次全局元素读取。第 10 课的 shared memory tile 会尝试复用这些输入。

## 本节通过条件

- 能从输入形状推导三个操作的结果形状。
- 能指出 `matmul` 内维不匹配与非 `f32` 类型为何非法。
- 能算出融合前后 `relu(add(A,B))` 的中间结果读写量。
