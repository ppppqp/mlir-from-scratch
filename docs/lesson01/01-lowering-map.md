# 第 1 课第 1 节：逐元素内核的降级草图

## 输入与语义

输入 `A, B: tensor<1024xf32>`，输出 `C: tensor<1024xf32>`：

```text
for i in [0, 1024):
  C[i] = max(A[i] + B[i], 0.0)
```

第一版由 C++20 教学编译器实现自己的 IR；下面的 `linalg.generic`、`scf.for` 等名称用于对照 MLIR 概念，不意味着依赖 MLIR 库。实际 IR 语法将在第 1 课第 2 节确定。

## 五层降级

| 层 | 草图 | 新增或确定的信息 |
| --- | --- | --- |
| Tensor IR | `%sum = add %A, %B; %C = relu %sum`，优化后可融合为一个类 `linalg.generic` 的逐元素计算 | 张量形状、元素类型、计算语义与逐元素迭代域 |
| Tiled IR | 将 `[0, 1024)` 分成长度 4 的 tile；每个 tile 内有 4 个元素的计算 | tile 的起点、大小及对原始索引的映射；仍可保留张量语义 |
| Buffer IR | 将张量映射为输入/输出 `memref`，显式表示地址、`load`、`store` 与必要的循环 | 可变存储、别名与访存行为；bufferization 与循环生成是两个独立步骤 |
| GPU IR | `t = block_id.x * block_dim.x + thread_id.x`，线程 `t` 处理 `[4t, 4t+4)` | block/thread 分工、每线程工作量、内存空间 |
| PTX | `.entry` 中读线程编号、计算地址、加载 4 个 `f32`，执行加法与 ReLU，最后写回 4 个结果 | 目标机器寄存器、指令、地址和 kernel 入口 |

用 `block_dim.x = 128` 时，网格需要 2 个 block，总共 256 个线程。线程 `t` 负责 `4t、4t+1、4t+2、4t+3`。因为 `t ∈ [0, 256)`，这些区间恰好覆盖 `[0, 1024)`，没有遗漏或重叠。

## 融合的性能意义

未融合时，`add` 的结果若作为独立 kernel 的输出，通常要写入一个中间缓冲区，再由 `relu` kernel 读回。融合后，`A[i] + B[i]` 可以留在寄存器中，紧接着计算 `max(..., 0)`，最终只写 `C[i]`。这可省去一次中间结果的全局写入和读取，也减少一个 kernel launch。实际延迟收益仍需在可运行 GPU 的环境中测量。
